# Best web scraping APIs in 2026 (Benchmarked)

A Python benchmark that compares ZenRows, Jina, Firecrawl, and CrawlForge across protected and unprotected websites. The benchmark measures successful content retrieval, response time, HTTP status, target status, content length, and request cost.

## Features

- Benchmark four web scraping APIs using the same target URLs
- Test websites protected by DataDome, Cloudflare, and Akamai
- Include an unprotected website as a baseline
- Execute repeated requests to measure retrieval consistency
- Measure response time for every request
- Detect unsuccessful responses based on returned content
- Record HTTP status, target status, page title, content length, response time, cost, and errors
- Save raw benchmark results as a CSV dataset

## Prerequisites

- Python 3
- A ZenRows account and API key
- A Firecrawl account and API key
- A CrawlForge account and API key
- A Jina account and API key is optional
- `requests`
- `python-dotenv`

## Installation

1. Clone the repository:

```bash
git clone <REPOSITORY_URL>
cd <REPOSITORY_DIRECTORY>
```

2. Create a virtual environment:

```bash
python3 -m venv .venv
```

3. Activate the virtual environment:

```bash
source .venv/bin/activate
```

4. Install the dependencies:

```bash
pip install -r requirements.txt
```

## Configuration

Create a `.env` file in the project root.

Add the provider credentials:

```text
ZENROWS_API_KEY=your_zenrows_api_key
FIRECRAWL_API_KEY=your_firecrawl_api_key
CRAWLFORGE_API_KEY=your_crawlforge_api_key
JINA_API_KEY=your_jina_api_key
```

Never commit `.env` or API keys to the repository.

## How it works

The benchmark sends the same four target URLs through each provider and records the result of every request.

```text
Target URLs
     ↓
Provider request
     ↓
HTTP response
     ↓
Extract returned content
     ↓
Validate meaningful content
     ↓
Record benchmark metrics
     ↓
results/raw_results.csv
```

The four targets represent different protection levels:

- JobLookup: DataDome
- Chrono24: Cloudflare
- Reuters: Akamai
- Wikipedia: Unprotected baseline

The benchmark evaluates success using the returned content rather than relying only on the provider's HTTP status. Returned HTML is checked for meaningful content, page titles, and common browser challenge or access-denied responses.

Each provider executes 50 requests against each target, resulting in:

- 50 requests per target
- 200 requests per provider
- 800 requests across all providers

Requests are sent at 2 requests per second with a 120-second request timeout.

## Troubleshooting

### Missing target URLs

If a target URL is missing from `.env`, the benchmark stops before sending requests.

Check that these variables are configured:

```text
JOBLOOKUP_URL
CHRONO24_URL
REUTERS_URL
WIKIPEDIA_URL
```

### Missing API keys

ZenRows, Firecrawl, and CrawlForge require their respective API keys. Jina can also use an API key through `JINA_API_KEY`.

### Requests marked as failures

A provider can return HTTP 200 while the target content is still unsuccessful. The benchmark checks the returned content for meaningful data and common challenge responses before marking a request as successful.
