# Best Web Scraping API for AI Agents in 2026

A Python benchmark that compares Zenrows, Jina, Firecrawl, and CrawlForge across protected and unprotected websites. The benchmark measures successful content retrieval, response time, HTTP status, target status, content length, and request cost.

> **Companion article:** [Best Web Scraping API for AI Agents in 2026](https://www.zenrows.com/blog/best-web-scraping-api-for-ai-agents)
> **Dataset:** [`results/raw_results.csv`](results/raw_results.csv) — 800 requests, one row each
> **Benchmark by:** Goodness E. Eboh

## Results

Average success rate across the three protected targets, 50 requests per provider per target:

| Provider | Protected-target success rate | Avg. response time (4 targets) |
|---|---:|---:|
| **Zenrows** | **100.00%** | 5,215 ms |
| Jina | 99.33% | 1,257 ms |
| Firecrawl | 66.67% | 1,497 ms |
| CrawlForge | 0.00% | 867 ms |

Firecrawl returned a reCAPTCHA page on all 50 DataDome requests. CrawlForge was refused on all three protected targets: 403 on JobLookup and Chrono24, 401 on Reuters. Full per-target numbers are in [Benchmark results](#benchmark-results) below, and every one of them is reproducible from the CSV.

## Features

- Benchmark four web scraping APIs using the same target URLs
- Test websites protected by DataDome, Cloudflare, and Akamai
- Include an unprotected website as a baseline
- Execute repeated requests to measure retrieval consistency
- Measure response time for every request
- Detect unsuccessful responses based on returned content
- Record HTTP status, target status, page title, content length, response time, cost, and errors
- Save raw benchmark results as a CSV dataset

## How it works

The benchmark sends the same four target URLs through each provider and records the result of every request.

```text
Target URLs
     ↓
Provider request
     ↓
HTTP response
     ↓
Extract returned content
     ↓
Validate meaningful content
     ↓
Record benchmark metrics
     ↓
results/raw_results.csv
```

The four targets represent different protection levels:

- JobLookup: DataDome
- Chrono24: Cloudflare
- Reuters: Akamai
- Wikipedia: Unprotected baseline

The benchmark evaluates success using the returned content rather than relying only on the provider's HTTP status. Returned HTML is checked for meaningful content, page titles, and common browser challenge or access-denied responses.

Each provider executes 50 requests against each target, resulting in:

- 50 requests per target
- 200 requests per provider
- 800 requests across all providers

Requests are sent at 2 requests per second with a 120-second request timeout.

## Output

The benchmark generates:

```text
results/raw_results.csv
```

The CSV records one row per request:

| Column | Meaning |
|---|---|
| `timestamp` | UTC time the request completed |
| `provider` | `zenrows`, `jina`, `firecrawl` or `crawlforge` |
| `target` | `joblookup`, `chrono24`, `reuters` or `wikipedia` |
| `protection` | Anti-bot system on the target, or `Unprotected` |
| `request_number` | 1-50 within that provider/target pair |
| `http_status` | Status the provider returned to us |
| `target_status` | Status the *target* returned, where the provider reports it. This is where CrawlForge's 403s and 401s show up behind an HTTP 200 |
| `success` | `True` only if the response carried a valid title or meaningful content |
| `page_title` | Title parsed from the returned HTML, useful for spotting challenge pages |
| `content_length` | Bytes returned |
| `response_time_ms` | Wall-clock time for the request |
| `cost` | Provider-reported cost where available. Populated for Zenrows and CrawlForge; empty for Jina and Firecrawl, whose usage was read from their dashboards instead |
| `error` | Exception text, where the request raised one |

Reproduce any published figure with a few lines of pandas:

```python
import pandas as pd

df = pd.read_csv("results/raw_results.csv")
protected = df[df.protection != "Unprotected"]
print(protected.groupby("provider").success.mean().mul(100).round(2))
```

## Reproducing this benchmark

Re-running will not reproduce these numbers exactly, and that is expected:

- **Anti-bot posture changes.** A target that blocked one provider in August may not in December, and the reverse. These figures describe August 2026.
- **The run was two sittings.** Zenrows, Jina and CrawlForge ran on 2026-08-20; Firecrawl ran on 2026-08-25.
- **Results depend on the plan.** Concurrency limits and proxy pools differ by tier, and each provider was run on the plan named in its dashboard reading.
- **Geography matters.** Requests were sent from a single location; a target serving different content by region will shift the content checks.

What should reproduce is the *method*: same targets, same 50 requests at 2 per second, same content-based success test for every provider.

## Troubleshooting

### Missing target URLs

If a target URL is missing from `.env`, the benchmark stops before sending requests.

Check that these variables are configured:

```text
JOBLOOKUP_URL
CHRONO24_URL
REUTERS_URL
WIKIPEDIA_URL
```

### Missing API keys

Zenrows, Firecrawl, and CrawlForge require their respective API keys. Jina can also use an API key through `JINA_API_KEY`.

### Requests marked as failures

A provider can return HTTP 200 while the target content is still unsuccessful. The benchmark checks the returned content for meaningful data and common challenge responses before marking a request as successful.
